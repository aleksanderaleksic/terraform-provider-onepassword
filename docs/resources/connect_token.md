# onepassword_connect_token (Resource)

Issues a token for a 1Password Connect server and writes it to a 1Password item. Changing anything but `name` issues a new token and revokes the old one. Requires desktop app authentication and the 1Password CLI (`op`) on `PATH`: service accounts and 1Password Connect can't manage Connect tokens.

## Example Usage

```terraform
resource "onepassword_connect_token" "operator" {
  server_id = onepassword_connect_server.cluster.id
  name      = "operator"

  vaults = [
    { id = onepassword_vault.cluster.uuid, access = "read" },
  ]
  expires_in = "90d"

  token_vault = data.onepassword_vault.admin.uuid
  token_title = "production-cluster Connect operator token"
}

ephemeral "onepassword_item" "operator_token" {
  vault = data.onepassword_vault.admin.uuid
  uuid  = onepassword_connect_token.operator.token_item_id
}

locals {
  operator_token = ephemeral.onepassword_item.operator_token.section_map["Connect token"].field_map["token"].value
}
```

## Requirements

Like `onepassword_connect_server`, this resource runs the 1Password CLI (`op`) and needs desktop app authentication: set `account` in the provider configuration. Service accounts and Connect can't issue Connect tokens.

## The token

`op` shows a token only when it is issued. The resource writes it to a secure note, `token_title` in `token_vault`. The note's section `Connect token` holds these fields:

| Field | Value |
|---|---|
| `token` | The token (concealed) |
| `server_id` | The UUID of the Connect server |
| `token_id` | The ID of the token |

The token never reaches state or plan. Read it with the ephemeral `onepassword_item`, as in the example above. If the item can't be written, the new token is revoked again.

## Changes and rotation

- **`name`** can be changed. The token is renamed.
- **Every other attribute** issues a new token, writes it to a new item, and revokes the old token. To rotate a token without other changes, replace it: `tofu apply -replace=onepassword_connect_token.<name>`.
- **A token revoked outside Terraform**, or whose server was deleted, is removed from state, and the next apply issues a new one.
- **A deleted token item** makes the plan warn. Replace the token to issue a new one.

Every vault in `vaults` must be one the Connect server can access. `access` limits the token to `read` or `write`; without it the token has the server's access.

## Limitations

- **No import.** A token can't be shown again, so an existing token can't be imported.
- **Names must be unique among the server's active tokens**, because `op` only prints the token and the resource finds its ID by name.

## Schema

### Required

- `name` (String) The name of the token. It must be unique among the server's active tokens.
- `server_id` (String) The UUID of the Connect server to issue the token for.
- `token_title` (String) Title of the token item. The item is a secure note with the concealed field `token` and the fields `server_id` and `token_id`.
- `token_vault` (String) UUID of the vault to write the token item to.
- `vaults` (Attributes Set) The vaults the token can access. The Connect server must have access to each of them. (see [below for nested schema](#nestedatt--vaults))

### Optional

- `expires_in` (String) How long the token is valid, in op's duration format, such as `90d` or `12w`. Without it the token does not expire.

### Read-Only

- `id` (String) The ID of the token.
- `token_item_id` (String) The UUID of the token item.
