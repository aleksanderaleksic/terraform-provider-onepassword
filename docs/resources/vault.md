# onepassword_vault (Resource)

Manages a 1Password vault and its group access using service account or desktop app authentication. Not available with 1Password Connect. Destroying a vault deletes every item in it.

## Example Usage

```terraform
data "onepassword_group" "developers" {
  name = "Developers"
}

resource "onepassword_vault" "example" {
  name        = "Terraform managed vault"
  description = "Managed by Terraform"

  group_permissions {
    group_id = data.onepassword_group.developers.uuid
    permissions = [
      "read_items",
      "reveal_item_password",
      "create_items",
      "update_items",
    ]
  }

  group_permissions {
    group_id    = "3gjoowf6ofrcjldq5z7v6h3cde"
    permissions = ["read_items"]
  }

  # Destroying a vault deletes every item in it.
  lifecycle {
    prevent_destroy = true
  }
}
```

## Deleting a vault

Destroying the resource deletes the vault together with every item in it, and the items can't be recovered from Terraform. Set `lifecycle { prevent_destroy = true }` on every vault that holds secrets, as in the example above.

Changing `allow_admins_access` never replaces a vault. 1Password only accepts it when the vault is created, so a change is an error. To change it, change it in 1Password and update the configuration to match.

## Group permissions

Each `group_permissions` block sets the complete permission set of one group. A group that is not in any block is not managed. The resource does not grant or revoke its access, and changes to its access are not detected. Removing a block revokes that group's access.

Groups are identified by UUID. Use the `onepassword_group` data source to look a group up by name.

The permission names follow the 1Password SDK. Some are named differently in the 1Password apps and the `op` CLI:

| Permission | Name in the 1Password apps and `op` |
|---|---|
| `read_items` | `view_items` |
| `reveal_item_password` | `view_and_copy_passwords` |
| `update_items` | `edit_items` |
| `update_item_history` | `view_item_history` |
| `send_items` | `copy_and_share_items` |

The other permissions have the same name in both places: `create_items`, `archive_items`, `delete_items`, `import_items`, `export_items`, `print_items`, `manage_vault`, and `no_access`, which can't be combined with any other permission. Which permissions depend on each other depends on the account type, and 1Password rejects a set that is missing a dependency when the plan is applied.

## Importing an existing vault

```terraform
import {
  to = onepassword_vault.example
  id = "vaults/2hinhvewsxob5p3he2cr2ylihy"
}
```

Or with the CLI:

```shell
# Vaults can be imported using their Terraform identifier.
terraform import onepassword_vault.example vaults/2hinhvewsxob5p3he2cr2ylihy
```

After an import:

- **Group access is not adopted.** State holds no groups, so the first plan shows the configured `group_permissions` as added. If a configured group already has access with other permissions, the plan warns with its current and its planned permissions, because applying replaces them. Check these warnings before applying, for example for Administrators.
- **`allow_admins_access` takes the configured value.** It is never read from 1Password, so it is not checked against the vault.

Creating a vault fails when a vault with the same name already exists. 1Password allows several vaults with one name, so this check stops a vault that should have been imported from being created a second time.

## Limitations

- **Not available with 1Password Connect.** Use service account or desktop app authentication.
- **Service accounts** can only access vaults assigned to them or created by them. They can't manage a vault created with another authentication method or update vault metadata. They can only delete a vault, or manage its group permissions, if they created it.
- **`allow_admins_access` is not read back**, so a change made in 1Password is not detected.
- **Access for individual users is not managed**, only access for groups.

### Optional

- `allow_admins_access` (Boolean) Whether members of the Administrators group can access the vault. Defaults to `true`. 1Password only accepts it when the vault is created: changing it later is an error rather than a replacement, because replacing a vault deletes its items. An imported vault takes the configured value without checking it.

Groups omitted from this block are not managed, and importing a vault does not automatically adopt its existing group access. When a group starts being managed while it already has different access, the plan warns which permissions applying replaces. Use the `onepassword_group` data source to look a group up by name.
