# onepassword_service_account (Resource)

Creates a 1Password service account and writes its token to a 1Password item. The service account can't be changed, read or deleted by Terraform afterwards: destroying the resource only deletes the token item. Requires desktop app authentication and the 1Password CLI (`op`) on `PATH`.

## Example Usage

```terraform
data "onepassword_vault" "admin" {
  name = "Infrastructure admin"
}

data "onepassword_vault" "deploy" {
  name = "Deploy secrets"
}

resource "onepassword_service_account" "ci" {
  name       = "ci"
  expires_in = "90d"

  vaults = [
    { id = data.onepassword_vault.deploy.uuid, permissions = ["read_items"] },
  ]

  token_vault = data.onepassword_vault.admin.uuid
  token_title = "ci service account token"

  # Destroying only deletes the token item; the service account itself has to
  # be deleted in the 1Password web interface.
  lifecycle {
    prevent_destroy = true
  }
}
```

## Requirements

The 1Password SDK can't create service accounts, so this resource runs the 1Password CLI. That has two requirements:

- **Desktop app authentication.** Set `account` in the provider configuration. With `service_account_token` or Connect credentials the resource fails when it is planned: `op` refuses to create a service account while signed in as one. This means the resource can't run in CI with a service account. Someone runs it with their own account.
- **The 1Password CLI (`op`) on `PATH`**, integrated with the desktop app. The provider runs it as the configured account and ignores `OP_SERVICE_ACCOUNT_TOKEN`, `OP_CONNECT_HOST` and `OP_CONNECT_TOKEN`.

## What Terraform can and can't do

`op` can create a service account, but it can't read, change or delete one. Only the 1Password web interface can do that. So this resource does less than most:

| | |
|---|---|
| **Create** | Creates the service account and writes its token to a secure note. |
| **Read** | Only checks that the token item still exists. Changes made to the service account in 1Password, or its deletion, are not detected. |
| **Update** | Not possible. Every attribute can only be set when the service account is created, and changing one is an error. A replacement would leave the old service account behind, so the resource never plans one. To change a service account, create a new resource and delete the old service account in the web interface. |
| **Delete** | Deletes the token item and warns that the service account still exists. Delete it in the web interface. |
| **Import** | Not supported. A token can't be shown again. |

Use `lifecycle { prevent_destroy = true }` unless the service account is short-lived.

## The token

`op` shows a service account's token only when the service account is created. The resource writes it to a secure note, `token_title` in `token_vault`. The note's section `Service account` holds these fields:

| Field | Value |
|---|---|
| `token` | The service account token (concealed) |
| `service_account` | The name of the service account |

The token never reaches state or plan. Read it with the ephemeral `onepassword_item`. If the item can't be written, the token is lost; the error says so, and the service account has to be deleted in the web interface. `op` doesn't return an ID for the service account, so the resource's `id` is the token item's UUID.

## Schema

### Required

- `name` (String) The name of the service account. Can only be set when it is created.
- `token_title` (String) Title of the token item. The item is a secure note with the concealed field `token` and the field `service_account`. Can only be set when the service account is created.
- `token_vault` (String) UUID of the vault to write the token item to. Can only be set when the service account is created.

### Optional

- `can_create_vaults` (Boolean) Whether the service account can create vaults. Defaults to `false`. Can only be set when it is created. A service account needs this or at least one vault.
- `expires_in` (String) How long the service account is valid, in op's duration format, such as `90d` or `12w`. Without it the service account does not expire. Can only be set when it is created.
- `vaults` (Attributes Set) The vaults the service account can access. Can only be set when it is created. A service account can't access Personal, Private or Employee vaults. (see [below for nested schema](#nestedatt--vaults))

### Read-Only

- `id` (String) The UUID of the token item. op does not return an ID for the service account itself.
